| `BR-002` | Snapshot Isolation by Commit Sequence, First-Updater-Wins Conflicts, `NO-STEAL` Staging & Commit-Order WAL Durability | Every commit observed by the engine gets the next commit sequence number (`Mark_Committed`); a snapshot (`Take_Snapshot`) is the last number taken. A version `(Xmin, Xmax)` is visible to snapshot `S` iff `Xmin` committed with sequence `<= S` and `Xmax` is `0`, uncommitted, or committed with sequence `> S` (`Is_Version_Visible`); uncommitted versions are never visible, the writer's own included. Writers pass the snapshot they took when they started, and a write is refused with `Status_Tx_Aborted` (`Has_Write_Conflict`) when the document's newest version was created or deleted by another active transaction (first updater wins) or by one that committed after the writer's snapshot (no lost update), or when another active transaction staged pages for it. Updates keep the single prior committed version (`Has_Prior_Version`) for older snapshots and rollback. An update over a version that already has a prior drops that prior and raises `Read_Horizon` to the commit sequence of the version kept: a query at an older snapshot fails with `Status_Tx_Aborted` ("snapshot too old") instead of silently missing the document, also after the update rolls back (a rollback cannot resurrect the dropped version). Deleting a transaction's own new version reverts the document to that prior version, deleted by the transaction unless a committed transaction had already deleted it. A transaction whose failed `Ingest_Document` could not be truncated from the WAL is poisoned and its versions are rolled back at once; a failed `Delete_Document` whose Page 1 frame survives does not poison it, since the transaction's commit page supersedes that frame. TOAST pages go to the lowest free run; pages another active transaction staged stay reserved until it ends, since its commit writes every frame it staged (`ADR-019`). Active transactions stage pages only as `WAL_Frame_Data` frames (`NO-STEAL`); the durable `WAL_Frame_Commit` append is the commit point, after which `Commit_Tx` reports `Status_Ok` (and `Flush_Pending` if `.db` must still be repaired by redo; while such pages are pending, `Freeze_RAG_Engine` refuses with `Status_IO_Error`, and queries that need them fail with `Status_IO_Error`, since Stage 2 and parent chunks are read from `.db`). Page 1 of a commit carries only committed versions and the committing transaction's own. Recovery repairs torn WAL / `.db` tails, replays in commit order, and reports `Max_Seen_Tx` so transaction ids are never reused (`ADR-009`, `ADR-010`, `ADR-019`). | `src/nhe_o-transaction.ads`, `src/nhe_o-rag.ads`, [`storage-and-wal-format.md`](storage-and-wal-format.md) |
| `BR-003` | PostgreSQL Vector, Scale-Aware Quantization & PostgreSQL-Exact JSONB | Vector distance operators (`<->`, `<=>`, `<#>`, Hamming) require matching dimensions (`1 .. 4096`) and bounded finite components `[-1.0e6 .. 1.0e6]`; cosine distance is scale invariant (exactly `1.0` when a vector is all zero), `Int8` SQ8 is scale-aware with saturating dequantization, and retrieval returns the exact top-K. JSON must pass RFC 8259 validation with well-formed UTF-8 (surrogates only as `\u` pairs, no U+0000). JSONB documents parsed from text are objects of at most `512` bytes; every stored document has at most `16` distinct top-level keys (a duplicate key keeps the last value; a document built field by field through the Ada API may hold `16` values of up to `512` bytes each), keys of `1 .. 64` bytes of well-formed UTF-8 without U+0000 at every depth, at most `64` nesting levels including the root, and numbers inside PostgreSQL's `numeric` range. Text that is not valid JSON, not an object, or holds an empty key is always rejected as a syntax error, before any ingest limit is checked. `->` returns strings re-escaped and `->>` returns them decoded (`Is_Null` for JSON `null`), exactly as PostgreSQL; numbers, objects and arrays come back as their stored literal, jsonb-equal but not always text-equal to PostgreSQL's output (`1e2`, not `100`). `?` tests a top-level key, and `@>` follows PostgreSQL containment at every depth (scalars by value with exact numeric equality, objects key by key, arrays element-wise) (`ADR-003`, `ADR-015`, `ADR-017`). | `src/nhe_o-vector.ads`, `src/nhe_o-hnsw.ads`, `src/nhe_o-json.ads` |
| `BR-004` | Key-Value TTL, Bounded LRU Eviction & Slot-Exact `"KVMG"` WAL Durability | Every operation takes the caller's timestamp `Now` (non-decreasing). An entry with a TTL is expired when `Now >= Expires_At` and is never returned by `Get`, `Exists` or `TTL`; reads report it (`Status_Expired`) but never free it, so only logged writes change the slot layout. A SET first frees the key's own entry and then takes the first free slot, else the first expired slot, else the least recently used one (lowest slot on ties) of the `64` slots; `INCRBY` of an absent or expired key reuses that key's slot when it still holds one. `DEL` at `Now` reports a removal only for a live key but frees expired entries too. `INCRBY` accepts Redis `string2ll` integers only (no `+`, no leading zeros, no `-0`) and rejects overflow. Durable variants append a slot-hinted `WAL_Frame_KV` record (`"KVMG"`, CRC32) before acknowledging and roll the store back on WAL failure; `Recover_KV_From_WAL` applies each hinted SET to exactly its slot, so recovery reproduces keys, values, TTLs and slot layout including silent evictions. Read recency (`Last_Access` updated by `Get`) is not logged, but every checkpoint (explicit, automatic, or the one `nhe_o_close` runs) saves each slot's `Last_Access`: after a reopen, LRU order follows the recency saved by the last checkpoint, updated by later durable writes. Deliberate Redis deviations: `EXPIRE` with a TTL `<= 0` is rejected (Redis deletes the key) and a SET with TTL `0` means no TTL (`ADR-007`, `ADR-014`). | `src/nhe_o-kv.ads`, [`storage-and-wal-format.md`](storage-and-wal-format.md) |
| `BR-005` | Dual-Mode Pub/Sub Delivery, `Owner_Tx` Guard & Overflow Accounting | Standard channels deliver messages in FIFO order immediately to matching active subscribers (exact channel or general `*` glob wildcard pattern at any position) in bounded ring buffers of `Queue_Capacity = 16` messages: when a subscriber's ring is full the new message is dropped for it (drop-newest), counted in its `Dropped` and not in the publisher's delivered count (the C ABI and the Python SDK do not expose `Dropped`). `Durable` transactional notifications (`Stage_Notify`) verify `Staging.Owner_Tx = Ctx.Id` and are dispatched to subscribers iff `Ctx.State = Tx_Committed` (`Flush_Committed_Notifications`), or discarded by the owning transaction on `Rollback_Tx` (`ADR-004`). | `src/nhe_o-pubsub.ads`, `src/nhe_o-transaction.ads` |
| `BR-006` | 4KB `"SLOT"` Primary Pages, `"TOAS"` Overflow Chains, `"RMET"` Metadata & `"VTS2"` Stage-2 Vector Re-Ranking | Primary tuples reside in 4096-byte `"SLOT"` slotted pages with 24B CRC32 headers and 16×8B line pointer directories. Oversized parent chunks, extended `Summary_Text` (`> 63B`) or `JSONB_Document` metadata exceeding inline limits (`Encode_Meta_TOAST`, `"RMET"` header), and the full embedding of every document at every dimension (`Encode_Vector_TOAST`, `8B` `"VTS2"` header + one exact IEEE 754 binary32 word per component, up to `16,392` bytes; legacy `"VTST"` payloads are still read) are persisted across non-overlapping contiguous linked 4KB `"TOAS"` overflow pages referenced by 16-byte `TOAST_Pointer` values, verified on startup recovery and Stage-2/Stage-3 RAG execution, a damaged chain failing the query or recovery closed (`ADR-003`, `ADR-006`, `ADR-018`). | `src/nhe_o-transaction.ads`, `src/nhe_o-vector.ads`, `src/nhe_o-rag.ads`, [`storage-and-wal-format.md`](storage-and-wal-format.md) |
| `BR-007` | Precondition-Free Defensive C ABI / FFI Boundary | Every `Convention => C, Export => True` subprogram in `Nhe_O.C_API` operates in `SPARK_Mode (On)` without raw C pointers (`chars_ptr`), carries no precondition, validates every untrusted scalar, length, timestamp, TTL and float before calling the SPARK engines, makes every stateful export check that an engine is open and was opened by the calling process (`C_Status_Not_Initialized` otherwise, also in a forked child; `nhe_o_analyze_sql`, the vector-distance calls and the version queries need no engine), and writes at most the documented capacity into caller buffers (the text plus a NUL only when shorter). The C runtime is one process-wide engine whose calls must be serialized. `C_Init_With_Paths` resolves symbolic links once, refuses aliased database / WAL / `"<wal>.ckpt"` paths and an existing database file whose first page is not zero (swapped arguments or any other file), never truncates a WAL path or database path that names another kind of file, takes exclusive `flock(2)` locks on both files (an open from another process fails with `C_Status_IO_Error`, while a new open in the same process first releases the open database; a checkpoint locks its new WAL before renaming it), reports a database of another dimension as `C_Status_Dimension_Mismatch`, and seeds ids above everything on disk; after an I/O error on a durable write every write is refused until the database is reopened (`ADR-005`, `ADR-012`, `ADR-013`). | `src/nhe_o-c_api.ads`, `src/nhe_o-c_api.adb`, `include/nhe_o.h` |
