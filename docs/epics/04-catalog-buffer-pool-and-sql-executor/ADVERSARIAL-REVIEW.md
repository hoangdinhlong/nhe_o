# Adversarial System Review (`v0.3.0` — Epics 01–03 Audit & Epic 04 Input)

_Date: 2026-10-17_

This document records the 24 verified findings (**7 Critical, 9 High, 5 Medium, 3 Low**) uncovered during the comprehensive adversarial review of **Nhé O (`v0.3.0`)** after completing Epics 01–03.

While `gnatprove 16.1.0` formally proves **100% Absence of Run-Time Errors (Silver AoRTE)** across all 26 files (`1,543 / 1,543` VCs: `601` Flow + `942` Provers, `0` unproved), AoRTE proofs only guarantee that no Ada run-time exception (`Constraint_Error`, `Program_Error`, `Storage_Error`) can occur. The findings below identify **semantic, algorithmic, durability, and FFI boundary gaps** that must be remediated in **Epic 04 (`04-catalog-buffer-pool-and-sql-executor`)**.

---

| `CRIT-01` | `Nhe_O.Transaction` / `Nhe_O.RAG` | **Missing Primary 4KB Slotted-Page Implementation & Volatile `RAG_Engine` State (`BR-006` / `ADR-001`):** No primary 4096-byte slotted-page layout (slot directory, line pointers, free-space offset, or on-page `MVCC_Tuple_Header` `Xmin`/`Xmax`) exists in `src/`. `RAG_Engine.Docs`, `PK_Tree`, and `Vector_Graph` reside only in RAM (`src/nhe_o-rag.adb:51-145`). | `CRIT-02` | `Nhe_O.BTree` | **Hardcoded Depth-2 Limit (Max 6 of 32 Nodes Used) & Failure on 13th Sequential Key:** `Route_To_Leaf` (`src/nhe_o-btree.adb:70-97`) only traverses 1 level below `Root_Node`, and `Insert_Key` (`lines 195-199`) fails with `Status_Capacity_Exceeded` when `Root_Node` has `Max_Keys_Per_Node = 4` keys (`5` leaves) and a leaf splits. `26` of `32` nodes in `BTree_Node_Pool` are unreachable, and sequential ascending/descending insertions fail on the **13th key** (before `Max_RAG_Docs = 16`). `Range_Scan` (`line 289`) also hardcodes `Cur_Node := 1` without checking `Kind = Node_Leaf`. | Epic 04 Task 0 |
| `CRIT-03` | `Nhe_O.BTree` | **Broken Node Page Serialization (`Encode_Node_Page` / `Decode_Node_Page`):** (`src/nhe_o-btree.adb:340-439`) (1) Never serializes `Node.Children (1 .. 5)` for internal nodes; (2) silently truncates `Integer_64` keys outside `0 .. 2^32 - 1` to `0`; (3) silently accepts out-of-range pointer fields (`Valid := True` with default pointer values); and (4) omits a 32-bit page CRC32 checksum. | Epic 04 Task 0 |
| `CRIT-04` | `Nhe_O.Transaction` / `Nhe_O.RAG` | **Broken MVCC Snapshot Isolation (`BR-002`):** (`src/nhe_o-transaction.ads:17-35`, `src/nhe_o-rag.adb:77-144`) (1) No Commit Log (`CLOG`) or rollback undo exists—if a transaction mutates `Engine.Docs` and calls `Rollback_Tx`, its tuple has `Xmin <= Snapshot` and remains permanently visible to later queries; (2) `Engine.Docs` has only one slot per `Doc_Id`, so updating `Doc_Id` in `T2` overwrites `Xmin := T2` in-place, destroying visibility for snapshots `S in T1 .. T2 - 1`; (3) `Xmax` is never set to a non-zero value anywhere in `src/`. | Epic 04 Task 0 & Task 3 |
| `CRIT-05` | `Nhe_O.Transaction` | **WAL Protocol (`BR-002`) Lacks Commit Markers, Mutates `.db` Before Commit, and Replays Uncommitted Frames:** (`src/nhe_o-transaction.adb:89-160, 383-466, 579-625`) `Encode_WAL_Frame` lacks a commit-frame flag in its reserved header bytes (`17 .. 24`), `Write_TOAST_Chain` writes `.db` pages before `Commit_Tx` (`STEAL` without `UNDO`), `Redo_WAL_Recovery` replays uncommitted transactions, and WAL recovery stops silently at `Max_Frames` without checkpoint/truncation. | Epic 04 Task 0 & Task 2 |
| `CRIT-06` | `Nhe_O.HNSW` | **Neighbor Slot-4 Overwrite Orphans Nodes `5 .. N-1` in `Insert_Vector`:** (`src/nhe_o-hnsw.adb:70-88, 143-168, 311-368`) `Insert_Vector` fills all 4 neighbor slots of `New_Id` with the first 4 existing nodes (`1, 2, 3, 4`) regardless of distance, and `Add_Directed_Edge` overwrites slot 4 of nodes `1 .. 4` with `New_Id` for every `New_Id >= 6`, severing all edges from `{1, 2, 3, 4}` to nodes `5 .. New_Id - 1`. In `Search_KNN`, queries with `K <= 5` never visit nodes `5 .. Node_Count - 1` (0% recall on orphaned nodes), while queries with `K >= 6` (such as `RAG` with `K = 16`) fall back to a full $O(N)$ linear scan (`lines 345-368`). | Epic 04 Task 0 |
| `CRIT-07` | `Nhe_O.HNSW` / `Nhe_O.Vector` / `Nhe_O.RAG` | **Vector & HNSW Semantic Defects:** (`src/nhe_o-hnsw.ads:23-47`, `src/nhe_o-hnsw.adb:19-68`, `src/nhe_o-vector.adb:250-290`, `src/nhe_o-rag.adb:109-134`) (1) `HNSW_Node` truncates `Float32` and `Int8` vectors to 64 dimensions (`Float_Pref`/`Int8_Pref`) without Stage-2 TOAST re-ranking (`Q-003`); (2) `Int8_L2_Distance_Squared` and `HNSW.Node_Distance` ignore `Quantized_Int8_Vector.Scale`; (3) `HNSW.Node_Distance` (`Encoding_Float32`) returns squared L2 instead of $\sqrt{\text{L2}^2}$; (4) `Dequantize_From_Int8` zeroes vectors when `Scale > Max_Component / 127.0`; and (5) updating an existing `Doc_Id` in `Ingest_Document` leaves the old `HNSW_Node` active, returning duplicate `Doc_Id` hits that pair stale vector distances with updated document metadata/text. | Epic 04 Task 0 |
